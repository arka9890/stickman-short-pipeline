# Pipeline Playbook — local stickman history Short

Six phases. Each has what we did, why, and the fixes that cost us time.

## Phase 0 — Project layout
One project folder per video:
```
first-paper/
  src/FirstPaper.tsx    # per-scene formula composition (frames from audio)
  src/Root.tsx          # Composition (durationInFrames MUST be integer!)
  src/timeline.json     # generated by scripts/make-timeline.mjs
  src/captions/captions_segN.json   # whisper output, per segment
  public/audio/vo_segN.wav          # normalized VO per segment
  scripts/make-timeline.mjs         # builds timeline from audio durations
  scripts/genvo_kokoro.py           # local TTS synth
  scripts/normalize-vo.mjs          # VO normalizer (-16 LUFS)
  scripts/transcribe.mjs            # whisper caption transcription (--force)
  scripts/master-final.mjs          # two-pass loudnorm master
  out/first-paper.mp4               # final deliverable
```

## Phase 1 — SEO keyword research (do FIRST, before script)
Required: also verify US-audience demand with real data BEFORE hook options,
and log provenance (numbers, not hunches):
1. Wikipedia pageviews REST API, monthly, last 2-3 months, for the topic and
   its main figures/facts:
   `https://wikimedia.org/api/rest_v1/metrics/pageviews/per-article/en.wikipedia/all-access/user/<Topic>/monthly/<YYYYMM01>/<YYYYMM01>`
   Gives US/global interest level and trend (rising demand pre-season, e.g. Santa/Krampus before Christmas).
2. Existing competition: `yt-dlp --dump-json --skip-download "ytsearch8:<topic> dark history shorts"`.
   Record top titles + view_count; note the angle gap your hook can own.
   If yt-dlp output is huge, pipe through a saved `.out` file and Select-String `"title":|"view_count":`.
3. Autocomplete intent: `node scripts/keyword_autocomplete.mjs "seed phrase 1" ...`
   (see below). Only pick a primary keyword that actually appears.
If a general web search API is unavailable, steps 1-3 still work (no keys).
Real autocomplete data = free, no API key. Run:
```
node scripts/keyword_autocomplete.mjs "seed phrase 1" "seed phrase 2" ...
```
- Endpoint Google/YouTube suggest: `suggestqueries.google.com/complete/search?client=youtube&ds=yt&hl=en&q=...`
- Response format: `window.google.ac.h([...])` — JSON inside first `[` and last `]`.
- The seed itself appearing first in autocomplete = validated high-demand phrase.
- Pull YouTube suggestions AND local-language Google suggestions; pick primary
  keyword only from phrases that actually appear.
- Title formula (YouTube): primary keyword in first 40 chars, total ≤100 chars,
  ≥3 variants, one with the current year. Description: primary keyword + key
  facts in the first 150 chars, then "WHAT YOU'LL LEARN" bullets (each bullet =
  another keyword signal), then 1 engagement question.
- Tags list: exact phrases from autocomplete (≤30 chars each, ≤500 total).
- TikTok: 4–5 hashtags only; EN + ID variants; same validated keywords in text.

## Phase 2 — Script + VO
- Hook-first (loop callback): before drafting vo.txt, send the USER a list of 3-5 hook options. Each option pairs (a) an opening hook line and (b) a closing line that calls back to that hook. Wait for approval, then write the full 6-segment script where seg1 carries the hook and the final segment closes with the matching callback.
- Script format `SegN::text` in `stills/vo.txt` (5–7 segments, each 5–8s).
- Default VO engine: Kokoro-82M ONNX (kokoro-v1.0.onnx + voices-v1.0.bin); Piper fallback only.
   en_US-ryan-high.onnx) for English; Kokoro-82M ONNX (`kokoro-v1.0.onnx`
   + `voices-v1.0.bin`) installed and usable as fallback.
- Local TTS: Kokoro-82M ONNX (`kokoro-v1.0.onnx` + `voices-v1.0.bin`). Pick 3–5
  candidate voices, generate a sample MP3 of each, let the USER choose.
- Env gotcha: if two Python installs exist, call the exact interpreter that
  has the deps; `pip` and `python` may belong to different versions.
- Voice generator: synth → trim leading/trailing silence → write WAV.
- Normalize each VO segment to -16 LUFS before mixing.

## Phase 2.5 - Stills (gflow-cli)
- Engine: gflow-cli text-to-image. `scripts/generate-stills.mjs` calls
  `gflow image t2i <prompt> --aspect 9:16` with `GFLOW_CLI_OUTPUT_DIR=public/assets`
  and writes a `_DONE` marker per shot id, so re-runs skip finished stills.
- Prompts live in `stills/prompts.mjs`: anchor style + era + cast + per-shot image
  + tail. One per-segment filter arg (`node scripts/generate-stills.mjs seg3`)
  generates a single segment's two scenes.
- Verify `gflow --version` (0.92+) is on PATH BEFORE generating; if missing, stop
  and tell the user. Do not fall back to other image generators silently.
- Gate 2 applies here: show each still one by one until three consecutive
  approvals; after that the rest may be batch-generated with the same A5 QA check.

## Phase 3 — Timeline + captions
- Slot timing per segment (not fixed): LEAD ~0.3–0.4s before audio starts
  (image lands slightly before narration), TAIL ~0.5–0.7s after audio ends,
  END_HOLD ~2.5–3.2s for the end card. Keep total dead air per scene under
  ~1.2s so audience retention doesn't drop.
- Total length is capped at 60.0 s / 1800 frames @30fps. Put the cap in
  `make-timeline.mjs` (e.g. shrink END_HOLD, then throw if the sum still
  overflows) and cut script words instead of squeezing the end card. Verify
  with `ffprobe -show_entries format=duration` on the rendered file.
- Place the end-card overlay relative to the scene end
  (`visualFrom + visualDur - endCardFrames`), not a hardcoded delay, so a
  shorter timeline can't clip it.
- `durationInFrames = Math.round(timeline.durationSec * fps)` in Root.tsx —
  Remotion throws if it's a float (we hit a 1517.58999 crash).
- Captions: transcribe the actual VO with whisper (medium.en, ~1 min/segment
  on 4 CPU threads), `--force` to overwrite. Never hand-write captions; the
  transcription is what guarantees sync.

## Phase 4 — Render
May use Concat MCP transitions/effects library when needed (keep <=0.4s).
`npx remotion render <CompId> out/video.mp4 --overwrite` (run in background,
report ETA). ~3 min for a 50s/1518-frame 9:16 project. Confirm render success
before moving on; if the bundle fails, it errors in the first minute.

## Phase 5 — Master + verify (two-pass loudnorm)
1. `node scripts/master-final.mjs` — pass 1 measures input, final pass applies
   `loudnorm=I=-14:TP=-1.5:LRA=11` + alimiter. TP target -1.5 (not -1.0):
   the AAC encoder overshoots true peak, so -1.0 pre-encode lands at -0.9.
2. MEASURE THE ENCODED FILE, not the intermediate:
```
ffmpeg -i out/video.mp4 -af ebur128=peak=true -f null NUL 2> ebur.txt
```
   Accept -14.0 ± 0.5 LU and peak ≤ -1.0. If outside: re-run master once
   (it is iterative) and measure again. Wrong-number sessions we saw:
   -14.8 (out of tolerance) fixed by one more pass → -14.4.

## Phase 5.5 — BGM theme fit
Choose BGM by topic/era (research); never reuse old BGM without explicit fit check.
Choose a BGM theme that matches the video's era/topic — e.g., Mesopotamian flute/lyre for Babylon, not a generic music-box from a previous video. Duck curve: music sits ~21 dB under the -16 LUFS voice while someone speaks, and 8 dB louder in speech gaps, with a 0.3 s attack/release so it never ducks audibly hard.

## Phase 6 — Visual QC + deliver
Extract stills and LOOK at them (multimodal read), covering:
- hook caption visible ~0.5s in, first scene
- every scene's first second (transition dips must not be full black)
- overlay/title positions vs subtitle zone (we shipped a version with a
  title colliding with captions — one 'pos: bottom' title among
  'pos: top' siblings; put scene titles at TOP)
- end card right after the last spoken word
- last frame fade-out
Fix code → re-render → re-master → re-check. Attach with
`tools.openbot.attach_files_to_response([abs path])`, then a short summary in
the user's language listing changes, measured loudness, and what was checked.

## Metadata delivery (Phase 1 output, reused at delivery)
Give: 3 YouTube title variants, full description (150-char lead + bullets +
question), 8–10 tags, and TikTok EN + ID captions with ≤5 hashtags each.
State which keyword data (autocomplete) backs the choices; if you could not
get real data, say so explicitly and fall back to playbook heuristics.
\n- BGM generation: ALWAYS create a new topic-fit BGM per video.
